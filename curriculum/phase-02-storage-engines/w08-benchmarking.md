# W08：怎样评价一种配置是否更好？

## 核心问题

吞吐提高时，是否牺牲了尾延迟、持久化或后台资源？怎样建立公平的比较？

## 理论与设计（1.5 小时）

- DDIA 第一版第 1 章：负载描述、延迟分位数；回顾第 3 章存储引擎取舍。
- [RocksDB Benchmarking tools](https://github.com/facebook/rocksdb/wiki/Benchmarking-tools)：查明所用 `db_bench` 版本支持的参数与统计。

## 目标源码（1 小时）

找到 `db_bench` 对应工作负载的生成、计时与统计逻辑，确认读写次数、线程数、值大小和同步选项如何落到调用。再选一处与实验变量有关的实现。

## 验证步骤（2 小时）

1. 从 W07 选一个变量，如写缓冲区大小；固定引擎提交、线程数、键值分布、数据量、WAL / sync、预热方式和数据库初态。
2. 跑基线与对照，各重复至少三次，记录完整命令、吞吐、可用延迟分位数、资源和整理统计。
3. 保留所有运行结果，不只选最好的一次；解释波动与后台任务影响。
4. 写出“在什么负载和条件下更好”，并单独列出未测到的恢复或设备层行为。
