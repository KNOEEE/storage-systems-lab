# W12：节点恢复和集群恢复一样吗？

## 核心问题

一个暂时离线的成员追赶日志，与从备份重建集群，分别依赖什么信息和身份？

## 理论与设计（1.5 小时）

- [Raft 论文扩展版](https://raft.github.io/raft.pdf)第 7 节：快照与日志压缩。
- [etcd 灾难恢复](https://etcd.io/docs/v3.6/op-guide/recovery/)：快照备份、校验与恢复，使用与实际安装版本一致的工具说明。

## 目标源码（1 小时）

固定 etcd / raft 提交，定位接收或应用 Raft snapshot 的入口，再定位离线快照恢复工具入口。记录它们处理的对象和触发方式，不把备份文件和 Raft 网络快照混为同一种工作流。

## 验证步骤（2 小时）

1. 为 W09 集群写入可核对数据，按版本文档导出快照并记录校验信息及 revision。
2. 在新目录、独立端口与集群标识下恢复，保留原测试集群的数据目录；核对键值与成员信息。
3. 与 W10 原节点重启追赶作比较，说明身份、数据来源与可恢复时间点。
4. 列出快照时间点之后的写入是否包含在恢复结果中。不能仅以进程启动成功宣称数据恢复完成。
