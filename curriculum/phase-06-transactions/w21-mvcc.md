# W21：多个事务怎样看到不同版本？

## 核心问题

同一个键为什么可以同时保留多个版本？事务的 start timestamp、commit timestamp、锁和读取可见性如何配合？

## 理论与设计（1.5 小时）

- DDIA 第一版第 7 章：快照隔离、写冲突与可能出现的异常。
- [TiKV Percolator](https://tikv.org/deep-dive/distributed-transaction/percolator/)：时间戳、锁与多版本状态；先读传统事务模型。

## 目标源码（1 小时）

固定 TiKV 提交，定位事务存储层的 MVCC 读、锁检查与提交记录查找，选一个快照可见性或写冲突测试。画出逻辑版本到引擎 key 的关系，不要求理解全部编码细节。

## 验证步骤（2 小时）

1. 使用事务客户端而非 RawKV，记录客户端、隔离级别及实际事务路径配置。
2. 先写初值，开启事务 A 读取；事务 B 修改并提交；再由 A 与新事务 C 读取，运行前写下预测。
3. 另外构造两个事务修改同一键的冲突，记录哪一步检测、错误或重试如何发生。
4. 将读到的结果对应到时间戳与锁状态。客户端自动重试可能改变可观察行为，须记录或控制。
