# W16：同样存数据，接口为什么不同？

## 核心问题

文件、对象和块接口向应用暴露了什么语义？相同底层存储为什么可以支撑不同接口？

## 理论与设计（1.5 小时）

- [Ceph Architecture](https://docs.ceph.com/en/latest/architecture/)：RADOS 与 RGW、RBD、CephFS 的关系。
- DDIA 第一版第 6 章：分区与路由的相关主题。先区分用户看到的命名空间、客户端寻址方式与底层数据放置。

## 目标源码（1 小时）

固定 Ceph 提交，分别定位对象网关、块设备客户端和文件系统客户端的入口目录。只选择一种接口追到 RADOS 请求，记录转换前后的对象标识与操作语义。

## 验证步骤（2 小时）

1. 选一个具体需求，例如“保存训练 checkpoint 并让多台机器读取”。写清是否需要目录、随机覆盖、共享写入和原子重命名。
2. 分别用文件、对象、块接口描述应用的读写流程，列出由应用额外承担的目录、索引、并发与故障处理。
3. 结合官方接口说明和目标源码核对至少一个语义差异，不将对象 API 默认解释成 POSIX 文件语义。
4. 画 Ceph 接口到 RADOS 的关系图。此次为接口与设计验证，不要求部署全部服务，也不产生吞吐结论。
